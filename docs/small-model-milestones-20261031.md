# Small-model milestone experiments (2026-10-31)

The evaluator's assisted milestone protocol produced working elevator simulations with Nanbeige4.3-33B Q4_K_S, Flint Q4_K_M, and Swift 1.5 Qwen3.8 27B Q4_K_S. These are supervised, guided results, not unmodified benchmark passes. See `~/Code/llm-eval/docs/small-model-experiments-20261031/SWIFT_TRIANGULATION.md` and `REPORT.md` for prompts, traces, checks, and limitations.

Swift used the existing `swift-1.5-27b` llama-swap profile (one slot, 262144 context, q8 KV). Its isolated Pi experiment advertised 65536 context and sent per-request `reasoning_budget_tokens: 128`, `tool_choice: required`, `parallel_tool_calls: false`, temperature 1 and top-p .95, with 4096 max output tokens. Those values are an experimental controller-owned action profile, not established universal defaults. The controller ended each action after a successful edit and an external evaluator checked progress; some repairs were supervised manually.

Do not force tool calls as a global interactive default: controller-owned milestones need a separate completion mechanism. Small output limits can truncate an entire tool call. Verify exact template, reasoning, and tool-call behavior independently per model/backend. The Nanbeige-only `tokenizer.ggml.add_space_prefix=bool:false` workaround addresses the confirmed SentencePiece `prepend_scheme=first` mismatch in llama.cpp commit 8ca4060b7 for ChatML requests; it is not a general fix for Swift, Flint, or arbitrary plain-text tokenization. A proper upstream implementation should honor the model's first-prefix setting.

The shared evaluator prototype is `~/Code/llm-eval/scripts/small_model_trial.py`. The experimental single-prompt variant is `~/Code/llm-eval/elevator_prompt_small_model_experimental.txt`; it has not yet been tested as a single prompt and does not itself enforce checkpoints. Automatic milestone selection, test gating, bounded retries, and progress tracking remain work to integrate into the harness.
